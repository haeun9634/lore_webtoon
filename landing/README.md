# landing — 캐릭터 시트 하나로 웹툰 1화

`story-harness` 와 `webtoon-harness` 의 최종 파이프라인을 **제품 화면 하나**로
감쌉니다. 쓰는 사람은 캐릭터 시트를 채우고 만들고 싶은 이야기를 한 줄 적고
버튼을 누릅니다. 조건 · 모드 · 그림체 문구 · 게이트 같은 것은 화면에 없습니다.

```bash
cd haeun/landing
../.venv/bin/python serve.py --open      # http://127.0.0.1:8800
```

## 처음 한 번

```bash
cd haeun && ./setup.sh
```

`.venv` 를 만들고 `landing/requirements.txt` 하나로 하네스 것까지
(`-r ../story-harness/...`) 전부 깝니다 — `Pillow` · `requests` · `PyYAML` ·
`openai` · `google-genai`. `anthropic` 은 `PROVIDER=anthropic` 을 쓸 때만
필요해서 주석 처리돼 있습니다.

시스템 파이썬에 그냥 깔면 안 되는 이유와 윈도우에서 손으로 하는 법은
`setup.sh` 안에 적혀 있습니다.

**서버는 반드시 이 venv 의 파이썬으로 띄웁니다.** 하네스를 하위 프로세스로
부를 때 `sys.executable` 을 그대로 쓰기 때문에(pipeline.py 의 `_run`),
시스템 파이썬으로 띄우면 화면은 뜨지만 **만들기를 누르는 순간** "openai
패키지가 없습니다" 로 멈춥니다 — 7% 에서 멈춘 것이 이것이었습니다.

API 키는 두 하네스의 `.env` 를 그대로 씁니다.

## 화면은 넷입니다

| | 주소 | 무엇 |
| --- | --- | --- |
| **랜딩** | `/` | 무엇을 만들어 주는지 · 어떻게 만드는지 · 실제 결과 예시 · 캐릭터 시트 입력 |
| **진행** | `/` | 지금 어느 단계이고 무엇을 하고 있는지. 그려진 장이 나오는 대로 붙습니다 |
| **결과** | `/result` | 세로 스크롤 리더 · 대사 스크립트 · `episode.png` 내려받기. **이미 만들어 둔 마지막 1화를 바로 엽니다** (`/?job=<id>` 로 특정 작업도) |
| **편집실** | `/editor` | **목업.** 한 번도 안 돌려도 열립니다 (아래) |

화면을 그냥 구경만 하고 싶을 때 여는 **목업** 이 셋 있습니다. 셋 다 실제 생성을
안 하고, 화면 코드는 본편과 **같은 것**을 씁니다 (베끼면 갈라집니다).

| 주소 | 무엇 | 데이터 |
| --- | --- | --- |
| `/demo` | 기다리는 화면 (단계·루·팁) | 가짜 진행 |
| `/demo/result` | 완성본 화면 | `web/samples/mock.json` |
| `/demo/mypage` | 마이페이지 | 가짜 계정 + 샘플 표지 |
| `/editor` | 편집실 | `web/samples/mock.json` |

`/demo/result` 의 「PNG 내려받기」는 **진짜 파일을 줍니다** — 샘플 장을 한 편으로
이어 붙인 뒤 실제 내려받기와 같은 길로 나가므로, LORE 표시가 붙은 모습이
목업에서 그대로 보입니다.

`/result` 는 `/api/latest`(가장 최근에 끝난 작업)를 보고 폼을 건너뛰고 결과부터
띄웁니다. 아직 만든 것이 없으면 안내를 띄우고 입력 화면으로 내려줍니다.

새로고침해도, 창을 닫았다 열어도 같은 화면으로 돌아옵니다 — 상태는 서버가
들고 있고 브라우저는 0.8초마다 받아 가기만 합니다. 10분 걸리는 일에서는
편의가 아니라 필수입니다.

## 버튼 하나가 부르는 것

```
1. story.py --character <job>/character.json --scenes 3 --no-read
2. story.py --charsheet --run-id <run> --yes
3. webtoon.py --run <run> --episodes 1 --skip-human-gate
4. run.py --run-id <run> --episode 1 --mode scene -c S+ --style <고른 것>
          --config <job>/config.yaml --yes
```

4번 하나가 그림과 `episode.png` 조립을 다 합니다.

### 왜 이 조합인가

| 고른 것 | 이유 |
| --- | --- |
| 조건 **S+** | 합격본입니다. 통합 시트 + **직전 컷**을 붙여서 조연이 같은 사람으로 이어지고 채색이 컷마다 갈리지 않습니다. `config.yaml` 자체가 "한 화를 통째로 뽑을 때는 S 가 아니라 S+" 라고 적고 있습니다 |
| **Scene 모드 · 한 장에 3컷** | 이미지 한 장 안에 컷 3개를 함께 굽습니다. 12컷짜리 한 화가 호출 12회 → **4회**, 2,200원 → 750원. 한 장 안은 같은 호출에서 그려지므로 저절로 통일됩니다 |
| **`lettering: in_image`** | 말풍선과 대사가 그림 안에 함께 그려집니다. 콘티의 한글 대사가 그대로 프롬프트에 실리고, 말풍선 모양(보통·외침·속삭임·속마음·나레이션)과 꼬리가 향할 사람까지 코드가 지정합니다 |

### 한 장에 3컷의 대가 — 두 가지를 내줍니다

**픽셀.** 캔버스 세로 2400px(9:16 · 2K)을 셋으로 나누므로 컷 하나가 800px 이
됩니다. 하네스 README 가 "얼굴이 작다는 느낌은 800px 아래에서 나오기 시작한다"
고 적어 둔 그 경계입니다. 얼굴이 작으면 `provider.options.image_size` 를 `4K` 로
올리세요 (컷당 픽셀이 2배, 장당 단가는 요금표 확인).

**여백.** 컷 모드에서는 콘티의 `gap_after` 를 보고 코드가 컷 사이 호흡을
정했습니다. 한 장 안에서는 그 배치를 모델이 정합니다.

되돌리려면 `pipeline.py` 의 `MODE` 를 `"cut"` 으로 바꾸면 됩니다 — 그 경로는
그대로 살아 있습니다.

### 3컷씩은 설정만으로 안 됐습니다 (하네스에 스위치를 하나 넣었습니다)

`max_cuts_per_scene: 3` 만 걸면 3컷이 **안 나옵니다.** 연출(W7.5)의 `scene_break`
가 경계를 정하고 상한은 큰 묶음을 *고르게* 쪼갤 뿐이라, 4+4+2+2 짜리 한 화에
상한 3을 걸면 3+1 이 아니라 **2+2+2+2+2+2** 가 됩니다. 3은 한 번도 안 나옵니다.

그래서 `webtoon-harness` 에 스위치를 하나 더했습니다 (추가 41줄 / 삭제 14줄):

```yaml
scene:
  grouping: rhythm     # rhythm(기본, 예전 그대로) | fixed(개수로 고정)
```

- **기본값은 `rhythm`** — 하네스의 동작은 한 톨도 안 바뀝니다. 같은 화를 원본
  config 로 돌리면 예전과 같이 `묶음 4, 4, 2, 2 · 연출 기준` 이 나옵니다.
- 랜딩페이지의 job config 만 `fixed` 로 둡니다 → `묶음 3, 3, 3, 3 · 3개씩 고정`.
- 코드는 `run.grouping_mode()` / `run.group_scenes()` 두 함수뿐이고, 흩어져 있던
  세 곳(본 생성 · `--verify-all` · probe)의 같은 삼항식을 그 함수로 모았습니다.

**리듬을 끄는 대가**: 경계가 이야기의 리듬과 무관하게 떨어집니다. 하네스가
`group()` 주석에 적어 둔 그대로 — "설명하다 만 자리에서 화면이 넘어가고, 궁금증이
남지 않는다". 리듬으로 되돌리려면 job config 의 `grouping: fixed` 한 줄만
지우면 됩니다.

## 하네스에 손댄 것은 스위치 하나뿐입니다

두 하네스는 완성본이라 원칙적으로 건드리지 않습니다. 제품 동작은 **바깥에서
주는 것**으로 만듭니다. 딱 하나 예외가 `scene.grouping` 인데, 바깥에서 줄 수 있는
값이 아예 없어서 넣었습니다 (위 참고 · 기본값은 예전 그대로).

### `<job>/config.yaml` — 원본을 복사해 다섯 값만 덮어씀

| 값 | 원본 | 여기 | 왜 |
| --- | --- | --- | --- |
| `style_default` | `lineart` | 사용자가 고른 것 | 시트와 컷이 같은 그림체를 봐야 합니다 |
| `scene.lettering` | `sfx_only` | `in_image` | 원본은 액션 컷에서 글자가 동작을 가리는 것을 막으려는 선택입니다. 제품에서는 대사가 보여야 합니다 |
| `scene.grouping` | `rhythm` | `fixed` | 연출 리듬 대신 개수로 자릅니다 (위 참고) |
| `scene.cuts_per_scene` | `2` | `3` | 한 장에 몇 컷 |
| `scene.max_cuts_per_scene` | `4` | `3` | 상한도 같이 내려야 합니다 |
| `character_appearance` | 청명 | `""` | **실험용 run 의 주인공 값입니다.** 그대로 두면 누가 들어와도 그 사람이 됩니다. 비우면 이 실행의 `p1.json` 이 기준이 되고, 그것도 없으면 `run.py` 가 스스로 멈춥니다 |
| `character_gender` | `male` | `""` | 같은 이유. `p1.json` 의 `gender` 가 이깁니다 |
| `outfit_lock` | 청명 도복 | `""` | 같은 이유. 아래 "알고 있는 것" 참고 |

`run.py` 는 config 안의 상대경로를 자기 `ROOT` 기준으로 풀기 때문에, 복사본이
다른 폴더에 있어도 그대로 돕니다.

### `WEBTOON_HARNESS_DIR=<job>` — 시트도 같은 그림체로

`story.py --charsheet` 는 그림체 문구를 **webtoon-harness 의 config** 에서
읽어 갑니다(`--style` 이 없습니다). 그 경로가 환경변수로 열려 있어서, job 폴더를
가리키면 시트도 사용자가 고른 그림체로 나옵니다. 이게 없으면 시트는 늘
`lineart`, 컷만 사용자가 고른 그림체가 되어 서로 다른 곳을 가리킵니다.

### `--skip-human-gate` — 블라인드 평가를 지납니다

`webtoon.py` 는 원래 사람이 "다음 화가 궁금한가"에 답해야 컷으로 넘어갑니다.
재미 판정은 하네스에서 사람만 하는 일이기 때문입니다. 랜딩페이지에는 사람을
세울 자리가 없어서 지나갑니다 — **재미가 검증됐다는 뜻이 아니라 그 관문이 없는
상태로 뽑은 결과라는 뜻입니다.**

## 진행 표시는 어떻게 아는가

하네스에는 진행률 API 가 없습니다. 대신 사람 보라고 찍는 줄들이 있고, 그 줄이
그대로 단계 표시가 됩니다. `pipeline.py` 의 `_story_line` / `_sheet_line` /
`_board_line` / `_art_line` 이 그 대응표입니다.

| 보이는 줄 | 화면에서 |
| --- | --- |
| `LOOK: 사진 1장 읽는 중` | 사진에서 외형 읽기 |
| `SEED: AI 가 정함 …` · `템플릿: …` | 장르·세계관 정하기 완료 → 캐릭터 카드 |
| `P3 [통과] 통과 8/8` | 구조 검수 완료 → 첫 장면 |
| `장면 점검 통과 (3장면)` | 이야기 설계 완료 |
| `sheet 후보 1 · 1024KB · 47초` | 시트 그리기 완료 |
| `4단계 통과: Arc 3개` | 큰 줄거리 완료 |
| `컷 12개 → Scene 4개 (묶음 3, 3, 3, 3 · 3개씩 고정)` | 묶기 완료 · 묶음 크기 표시 |
| `[3/4] scene_S+ / Scene3 / c1` | 그림 3/4 · 진행 막대 |
| `OK (41.2s) -> …/scene3_c1.png` | 그 장 썸네일이 화면에 붙음 |
| `episode.png -> …` | 한 편으로 잇기 완료 |

**못 읽는 줄은 그냥 로그로 흘립니다.** 표시가 한 칸 늦을 수는 있어도 틀린
단계를 보여주지는 않습니다. 하네스가 모든 전환을 찍지는 않으므로(P2 시작을
알리는 줄은 없고 P3 결과 줄만 있습니다), 뒤엣것이 보이면 앞엣것은 끝난 것으로
칩니다.

전체 stdout 은 `jobs/<job>/log.txt` 에 그대로 쌓이고, 화면의 「자세히 보기」가
그 꼬리를 보여줍니다.

## 기다리는 화면

웹툰 한 편이 나오기까지 10분 가까이 걸립니다. 그 10분을 세 가지가 나눠 맡습니다.

### 1. 위 — 지금 무엇을 하고 있는지

단계 그림 한 장 + 한 줄 + 진행 바 + 경과 시간. 그림은 `web/lou/stage/<단계>.webp`
여섯 장이 만드는 순서 그대로 바뀝니다 (이야기 → 캐릭터 → 콘티 → 그림 → 검수 →
완성). 글씨보다 그림이 먼저 읽히는 자리라 작게 두지 않습니다.

그 아래 **「지금 하고 있는 일 자세히」** 토글을 열면 단계 안쪽까지 보입니다 —
`캐릭터 시트 · 외형 사양 정리 → 시트 그리기 → 기준 시트 확정` 처럼요. 항목은
`pipeline.py` 의 `STAGE_SPEC` 이 그대로 올라오는 것이라, 단계를 늘리면 화면도
같이 늘어납니다. 기본은 닫혀 있습니다 — 대부분은 한 줄이면 충분합니다.

### 2. 가운데 — 루와 놀기

화면의 주인공입니다.

| 하는 것 | 루의 반응 |
| --- | --- |
| 한 번 누르기 | 반응 다섯 컷 중 **아무거나 하나** — 누를 때마다 다릅니다 |
| 연달아 누르기 | 누른 횟수만큼 점점 화납니다 (놀람 → 짜증 → 화남 → 삐짐) |
| 꾹 누르기 | 기다리다 졸고, 잠들고, 손을 떼면 깹니다 |
| 끌어당기기 | 손을 따라 헤엄칩니다. 놓으면 기뻐하며 제자리로 돌아옵니다 |
| **잡고 흔들기** | 끄는 중에 좌우로 마구 흔들면 눈이 핑 돕니다. 흔드는 동안에도 손은 계속 따라오고, 다 흔들면 끄는 모습으로 돌아옵니다 |
| 제자리에서 문지르기 | 쓰다듬는 것으로 보고 하트가 터집니다 |
| **폰 흔들기** | 물살에 휩쓸려 눈이 핑 돕니다 (모바일) |

**반응은 화면에만 있습니다.** 서버로 아무것도 안 보내고 돌고 있는 작업에도
영향을 주지 않습니다. 한동안 아무도 안 만지면 잠들고, 누르면 깹니다.

### 흔들기가 두 길인 이유

**잡고 흔들기**(끄는 중 방향 뒤집힘)가 사실상 본길입니다. 권한이 필요 없고
가속도계가 없는 PC 에서도 되기 때문입니다. 0.9초 안에 방향이 3번 뒤집히면
흔든 것으로 봅니다 — 사람이 손목으로 흔들면 한 번 뒤집는 데 150~250ms 라,
그냥 끌고 다니다 방향을 바꾸는 것과는 확실히 구분됩니다.

**폰 흔들기**(devicemotion)는 판정을 가속도 크기가 아니라 **변화량**으로
봅니다. 예전에는 `|x|+|y|+|z| > 34` 였는데,
`accelerationIncludingGravity` 에는 중력(9.8)이 섞여 있어서 기기를 어느 쪽으로
들고 있느냐에 따라 가만히 있어도 기준값이 달라졌습니다 — 어떤 자세에서는 세게
흔들어야 겨우 넘고, 어떤 자세에서는 걷기만 해도 넘었습니다. 앞뒤 표본의 차이를
보면 중력이 저절로 빠지고 자세와 무관해집니다.

흔들기는 iOS 13+ 에서 **사람이 허락해야** 동작합니다. 그 창은 사람이 무언가를
누른 직후에만 열 수 있어서, 루를 처음 누를 때 같이 묻고 거절했거나 아직 안
물어본 기기에는 「흔들기 켜기」 버튼을 보여 줍니다. 안드로이드·데스크톱은
허락이 필요 없어 바로 켜집니다.

### 3. 아래 — 팁 · TMI

그냥 읽을거리입니다. 몇 초마다 다음 것으로 넘어가고, 누르면 바로 다음 것이
나옵니다. 한 바퀴를 다 돈 뒤 다시 섞기 때문에 같은 것이 연달아 나오지 않습니다.

내용은 **`web/lou/tips.json`** 에만 있습니다 — 팁을 늘리거나 고칠 때 코드는 안
건드려도 됩니다. `kind` 는 `"팁"`(쓸모 있는 것)과 `"TMI"`(루에 대한 실없는 것)
두 가지이고, `seconds` 로 넘어가는 간격을 바꿉니다.

```json
{ "seconds": 9,
  "items": [
    { "kind": "팁",  "text": "이야기를 자세하게 쓸수록 정확도가 올라가요." },
    { "kind": "TMI", "text": "루는 생선을 별로 안 좋아해요. 좋아하는 건 미역이래요." }
  ] }
```

### 그림은 어디서 오나

그림은 `web/lou/react/<반응>/NN.webp` 이고, 어떤 컷이 있고 무슨 말을 하는지는
같은 폴더의 `manifest.json` 이 들고 있습니다 — 컷을 늘리거나 말을 고칠 때
`lou-play.js` 는 안 건드려도 됩니다. 원본은
`design-reference/interaction/` 에 있고, 골라서 줄여 오는 것은
`web/lou/_sync_react.py` 가 합니다 (그림체를 하나로 맞추고, 사람 손이 그려진
컷은 빼고, 전부 같은 320px 정사각 판형에 얹어 webp 로 굽습니다 — 판형을 안
맞추면 반응이 바뀔 때마다 루가 커졌다 작아졌다 합니다. 38컷 다 합쳐 300KB 가
안 됩니다). 같은 스크립트가 `design-reference/loading/` 의 단계 그림 여섯 장도
`web/lou/stage/` 로 가져옵니다.

`sleep`(잠드는 흐름)과 `wake`(깨는 흐름)를 나눠 둔 이유가 있습니다 — 한 덩어리로
두면 아무도 안 만졌는데 루가 혼자 깜짝 놀라며 깹니다. 깨는 컷은 자는 루를
눌렀을 때만 씁니다.

```
cd web/lou && python _sync_react.py
```

## 완성본 화면의 단추는 셋입니다

다 만든 뒤 처음 보는 화면이라 "완성"으로 읽혀야 하는데, 예전에는 단추가 여덟
개에 글자만 빽빽해서 관리 화면처럼 보였습니다. 지금은 루가 완성본을 들고 있는
그림을 표지로 깔고, 여기서 실제로 할 일 셋만 남깁니다.

| 단추 | |
| --- | --- |
| **내려받기** · **편집실로 가기** | 늘 |
| **서버에 저장하기** | 담을 작품이 있으면 늘 (아래) |
| **홈** | 늘 |

나머지(대사 스크립트 · 공유 · 목록으로 · 새로 만들기 · 다음 화 만들기 ·
다음 장면 이어서 보기)는 **다 읽은 자리**(`.read-end`, 리더 맨 아래)로
내렸습니다. "이어서 볼래?" 와 "남에게 보여줄래?" 는 읽기 **전**이 아니라 읽고
**난 뒤**에 생기는 마음이라, 머리에 둘 이유가 없습니다.

이 화면에서는 **아무것도 스크롤을 따라오지 않습니다** — 완성본 머리도 상단 바도
`static` 입니다. 웹툰은 그림을 보러 온 화면이고, 읽는 내내 화면 위를 차지하고
있으면 그림이 그만큼 줄어듭니다. (다른 화면에서 상단 바는 그대로 따라옵니다.)

### "서버에 저장하기"

로그인 여부와 상관없이 **늘 보입니다.** 로그인 전에 누르면 회원가입 창이 열리고,
가입·로그인이 끝나면 보고 있던 작품이 그대로 담깁니다(`pendingClaimRunId`) —
계정을 만들 이유가 처음 생기는 자리가 여기입니다.

이미 담은 작품이면 감추는 대신 눌리지 않는 **「✓ 저장됨」** 으로 바뀝니다.
감춰 버리면 단추가 셋에서 둘로 줄어 자리가 흔들리고, 저장이 됐는지 안 됐는지도
알 수 없습니다.

단추 아래에 왜 눌러야 하는지를 한 줄로 적어 둡니다 — "로그인하고 저장하면
마이페이지에서 언제든 다시 볼 수 있습니다. 저장 안 해도 이 브라우저에는
남습니다." 이유가 화면에 없으면 아무도 안 누릅니다.

## 마이페이지 (`/mypage`)

상단 바의 **「로그인」이 로그인 뒤 「마이페이지」로 바뀌고** 여기로 옵니다
(닉네임 대신 「마이페이지」라고 적는 이유: 닉네임만 있으면 그것이 눌러서 갈 수
있는 자리라는 것을 아무도 모릅니다. 닉네임은 안에서 크게 보여 줍니다).

| | `/works` 내 웹툰 | `/mypage` 마이페이지 |
| --- | --- | --- |
| 무엇 | 이 **서버**에 있는 작품 전부 | 이 **계정**에 저장한 것만 |
| 계정 | 필요 없음 | 로그인 필요 |

계정 없이도 만들 수 있는 서비스라 서버에는 로그인 전에 만든 것이 섞여 있습니다.
그래서 둘을 나눴고, 마이페이지에서 「이 서버의 작품 전부 보기」로 건너갑니다.

**크레딧도 여기 있습니다.** 상단 바 배지가 *알림*이라면 여기는 *자리* 입니다 —
얼마 남았는지 보고 충전할지 정하는 곳. 한 편에 얼마인지를 같이 적어서
("한 편에 120 C — 지금 10편 더 만들 수 있어요") 숫자만 보고는 알 수 없는
"많은가 적은가"를 바로 알 수 있게 했습니다. 잔액을 그리는 곳은
`paintCreditPill()` 하나라 상단 바와 마이페이지가 갈라지지 않습니다.

목록은 `/api/runs` 를 받아 계정의 `claimed_runs` 로 거릅니다 — 서버에 새 API 를
만들지 않아도 되고, 작품 카드 그리는 코드(`workCard`)도 `/works` 와 그대로
나눠 씁니다.

## 워터마크 — 나가는 파일에만

완성본을 **내려받거나 공유할 때** 파일에 LORE 표시가 붙습니다
([#117](https://github.com/SW-Maestro-TRY/Lore/issues/117)). 붙는 것은 둘입니다.

- **아래 브랜드 띠** — 루 + `LORE` + 「루와 함께 만든 웹툰」, 오른쪽에 작품·회차.
  그림 밑에 덧대는 자리라 작품을 안 가립니다.
- **반투명 코너 마크** — 그림 오른쪽 아래. 띠만 잘라내도 이건 남습니다.

**저장물은 안 건드립니다.** `episode.png` 도 `baked/` 도 그대로 두고, 내려받는
순간에만 표시를 얹은 사본(`<회차폴더>/download/*_wm.png`)을 만들어 내보냅니다.
이유가 셋입니다 —

1. 만드는 동안 보는 화면과 편집실이 깨끗해야 합니다. 작업 중에 계속 보이면
   방해가 되고, 편집기에서 얹은 말풍선과 겹쳐 보입니다.
2. 다시 구울 때 표시가 두 번 찍히는 사고가 구조적으로 안 납니다.
3. 나중에 "크레딧을 쓰면 표시를 뗀다"([#60](https://github.com/SW-Maestro-TRY/Lore/issues/60))로
   갈 때, 저장물에 박혀 있으면 이미 만든 작품은 영영 못 뗍니다.

**표시를 못 붙여도 내려받기는 됩니다.** 그림이 깨졌거나 글꼴이 없으면 원본을
그대로 내보냅니다 — 워터마크 때문에 파일을 못 주는 것이 제일 나쁩니다.

붙는 자리는 네 곳입니다: `/api/runs/<id>/episode.png` ·
`/api/runs/<id>/baked.png` (편집실의 「이미지로 뽑기」가 이것을 씁니다) ·
`/api/jobs/<id>/episode.png` · `/api/demo/episode.png` (완성본 목업).
결과 화면과 편집실 양쪽에 "내려받는 파일에는 LORE 표시가 붙습니다" 를 미리
적어 둡니다 — 받아 보고 나서 알면 "왜 붙었지?" 가 되고, 미리 알면 그냥
사실이 됩니다.
끄려면 `watermark.py` 의 `ENABLED = False`. 검사는 `python test_watermark.py`
(pytest 아님 — 마지막 줄에 `ALL PASS`).

## 편집실 (`/editor`)

`?run=<run_id>` 로 열면 **그 작품의 실제 1화**를 열고, 다시 그리기도 진짜로
그립니다. 그냥 열면(아래) 목업이라 서버 없이도 화면을 볼 수 있습니다.

### 목업으로 열었을 때

**아무것도 생성하지 않습니다.** 이미 만들어 둔 1화를 `web/samples/mock.json` +
`web/samples/mock/scene{1..4}.jpg` 로 떠 두고 그것만 읽습니다. 서버 상태도
job 도 필요 없어서 **한 번도 안 돌려 본 사람이 그대로 열어 볼 수 있습니다.**

완성본을 웹툰처럼 내려 읽으면서 장마다:

| 할 수 있는 것 | 목업이 하는 일 |
| --- | --- |
| **다시 그리기** `−40 C` | 그림 위에 기다리는 화면을 덮고, 크레딧을 깎고, 버전을 `v2` 로 올립니다 |
| **☐ 말풍선 없이** | 켜 두면 다음 재생성 요청에 실려 갑니다. 켠 장에는 `말풍선 없음` 표가 붙습니다 |
| **피드백** | **스토리 / 연출 / 그림** 세 칸으로 갈라 적습니다. 그 아래에 이 장에 들어간 컷의 대사가 그대로 깔립니다 |
| **피드백 반영해 다시 그리기** `−60 C` | 적은 칸만 요청 요약에 실어 보냅니다 |

오른쪽 도구로 **그림 위에 직접 얹습니다** — 끌어서 옮기고, 모서리로 크기를
바꾸고, 두 번 눌러 글자를 고칩니다:

- **말풍선** 6종 — 일반 · 외침 · 속삭임 · 속마음 · 나레이션 · 회상
  (하네스 `scene.bubbles` 의 6종과 같은 이름입니다)
- **스티커** 12종 — 💦 ❤️ ✨ 💢 ❗ …
- **효과음** 8종 — 쿵 · 우당탕 · 스윽 · 두근 …

**말풍선 없이 다시 그리기 → 오른쪽에서 직접 얹기** 가 이 화면이 그리는 흐름입니다.
그림에 구워진 한글이 마음에 안 들면 빼고 내가 놓는 것입니다.

### 크레딧은 전부 가짜입니다

`−40 C` / `−60 C` / 랜딩의 `−240 크레딧` 은 **화면에 보이려고 둔 숫자**이고 실제
과금과 아무 상관이 없습니다. 상단 「목업」 배지가 그 표시입니다. 값은
`web/editor.js` 의 `COST` / `START_CREDIT`, `web/app.js` 의 `CREDIT` 에 있습니다.

샘플(`/editor` 를 그냥 열었을 때)에서는 얹은 것 · 피드백 · 잔액이
**localStorage 에만** 남습니다. 실제 작품(`/editor?run=<run_id>`)을 열면 얹은
것은 작품 폴더에 저장되고 그림으로 구울 수 있습니다 — 바로 아래를 보세요.

### 얹은 것은 저장되고, 그림으로 구워집니다

예전에는 말풍선을 아무리 정성껏 놓아도 **브라우저 밖으로 나갈 길이 없었습니다.**
가져갈 수 있는 것은 말풍선 없는 원본뿐이었습니다. 지금은 둘 다 됩니다.

| | 어디에 | 무엇 |
| --- | --- | --- |
| **저장** | `outputs/<run>/ep1/overlay.json` | 얹은 것의 자리·글자·크기. 손을 멈추면 0.6초 뒤 자동으로 올라가고, 「저장」을 누르면 그 자리에서 올립니다. 브라우저를 비워도, 다른 기기에서 열어도 그대로입니다 |
| **굽기** | `outputs/<run>/ep1/baked/scene{n}.png` | 장마다 말풍선이 구워진 그림 |
| | `outputs/<run>/ep1/episode_baked.png` | 그것을 세로로 이어 붙인 한 편 |

「**이미지로 뽑기**」한 번이 저장과 굽기를 같이 합니다 (따로 왕복하면 그 사이에
실패했을 때 화면에 보이는 것과 구운 것이 갈립니다). 다 되면 위에 띠가 뜨고
거기서 내려받습니다 — `<주인공>_1화_말풍선.png`.

**원본은 안 건드립니다.** 말풍선을 옮긴 뒤 다시 구우려면 밑그림이 깨끗해야 하고,
굽기는 몇 번이든 다시 할 수 있어야 합니다.

얹은 것이 없는 장도 굽습니다 — 안 그러면 한 편으로 이을 때 어떤 장은 구운 것,
어떤 장은 원본이 되어 두 폴더를 섞어 읽어야 합니다.

**화면에서 본 그대로 나옵니다.** 자리(x·y·너비)는 퍼센트라 해상도와 무관한데
글자 크기만 CSS 픽셀이라, 편집실이 "그때 그 상자가 화면에서 몇 px 이었는지"를
같이 보냅니다(`ref_w`). 굽는 쪽은 `그림폭 / ref_w` 로 배율을 잡습니다.

> ⚠️ **스티커(이모지)는 서버에 이모지 글꼴이 있어야 그려집니다.** 맥(Apple Color
> Emoji)·윈도우(Segoe UI Emoji)에는 있습니다. 없는 서버에서는 스티커만 빠지고
> 나머지는 그대로 구워지며, 결과 띠가 무엇이 빠졌는지 말해 줍니다 — 조용히
> 사라지지 않습니다.

검사는 `python test_overlay.py` (두 하네스 테스트와 같은 방식 · pytest 아님).

## 시간과 비용은 어디에 남나

| 어디 | 시간 | 비용·토큰 |
| --- | --- | --- |
| `runs/<run>/calls.jsonl` | 호출별 `seconds` | 호출별 토큰·비용 |
| `runs/<run>/meta.json` | `elapsed_sec` | `usage.cost` |
| `runs/<run>/webtoon/calls.jsonl` · `meta.json` | 〃 (콘티 W4~W8) | 〃 |
| `runs/<run>/charsheet/charsheet_meta.json` | `usage.seconds` · `seconds_each` | `usage.cost_usd` |
| `outputs/<run>/ep1/log.jsonl` | 호출별 `duration_sec` | 프롬프트 전문 + 토큰·비용 |
| `outputs/<run>/ep1/usage.csv` | `duration_sec` 열 | 26열 전부 |
| `outputs/<run>/ep1/usage.json` | `total.seconds` + 종류·모델·조건·그림체별 | 〃 |
| `landing/jobs/<job>/state.json` | **단계별** `seconds` | — |

결과 화면 부제에 `5:30 걸림` 이 뜨고, 마우스를 올리면 단계별 내역이 나옵니다
(`이야기 설계 1:29 · 캐릭터 시트 0:18 · 콘티 1:21 · 그림 2:20 · 잇기 0:01`).

> ⚠️ **비용은 어림값입니다.** `config.yaml` 의 `pricing.rates` 가 비어 있으면
> 이미지는 장당 `provider.cost_per_image_usd`, 텍스트는 회당
> `text.cost_per_call_usd` 고정으로 계산합니다 — 첨부 1장짜리와 2장짜리가 같은
> 값으로 찍히고 thinking 토큰은 값에 안 들어갑니다. 아직 어림값인 호출 수는
> `usage.json` 의 `calls_priced_flat` 에 있고, 단가를 채우면 0 이 됩니다.
> **토큰과 시간은 어림값이 아니라 실측입니다.**

## 알고 있는 것 (고치지 않은 채로 둔 것)

**`outfit_lock` 을 비워 둡니다.** 하네스는 "기본 의상 한 벌"을 config 에 적어
컷마다 옷이 바뀌는 것을 막습니다. 그 값은 주인공마다 달라서, 사용자가 아무나
넣는 제품에서는 미리 적어 둘 수가 없습니다. 지금은 비우고 실행하며,
`run.py` 가 그때마다 경고를 찍습니다(로그에 남습니다).

완전히 무방비는 아닙니다 — `p1.json` 의 `design_details`(매 컷에 유지될 고정
요소)는 코드가 모든 프롬프트에 강제로 붙이고, 조건 `S+` 가 직전 컷을 붙여
줍니다. 그래도 사진을 여러 장 올려서 `appearance_en` 이 옷을 여러 벌 나열하게
되면 컷마다 옷이 달라질 수 있습니다. 그때는 `jobs/<job>/config.yaml` 의
`outfit_lock` 에 한 벌만 영어로 적고 그림 단계만 다시 돌리면 됩니다:

```bash
cd C:\lore\webtoon-harness
python run.py --run-id <run> --episode 1 --mode scene -c S+ --style <이름> \
              --config C:\lore\landing\jobs\<job>\config.yaml --yes
```

**두 번째 주연 시트와 존 배경은 뽑지 않습니다.** `story.py --second-lead` 와
`--zonesheet` 는 1화 이후에 의미가 있는 자산이라(명부가 쌓여야 합니다) 1화만
만드는 이 화면에서는 부르지 않습니다. 있으면 `charsheet.py` 가 알아서 읽어
가므로, 나중에 손으로 뽑아 두면 다음 화부터 그대로 반영됩니다.

**시트와 컷은 다른 모델이 그립니다** (시트 OpenAI · 컷 Gemini). 같은 그림체
문구를 줘도 손이 다릅니다 — 시트는 *무엇을 그릴지*의 기준이지 *어떻게 그릴지*의
보증이 아닙니다. 이건 하네스의 성질이고 여기서 바꾸지 않았습니다.
